# Study Quest

Сайт для тренировки школьной математики (Year 7, британская программа). Ребёнок решает сеты по 10 примеров. Если он решает **2 сета подряд без единой ошибки**, открывается время для компьютерных игр. Все числа меняются в настройках родителя.

- Весь сайт на английском: и экраны ребёнка, и панель родителя.
- Профили: в семье может быть несколько детей. У каждого свой прогресс, свои правила и темы и, по желанию, свой PIN. Родитель входит по своему PIN и видит всех детей.
- Работает на телефоне и на компьютере. Прогресс общий для всех устройств семьи (нужен хостинг с PHP, см. ниже).
- После каждой ошибки показывается правильный ответ, пошаговое решение и подсказка про типичную ошибку («Right number, wrong sign!», «5³ is not 5 × 3» и т. п.).
- Темы подключаются отдельными файлами, так что новые темы и предметы добавляются без переделки сайта.

## Что уже есть

| Тема | Уровни |
|---|---|
| Times tables | 2–10 · до 12 × 12 с делением · числа с нулями (30 × 7, 240 ÷ 6) |
| Negative numbers: + and − | числовая прямая (−7 + 3, 4 − 9) · два знака рядом (5 − (−8)) и температура · смешанные (большие числа, три слагаемых, пропущенное число) |
| Negative numbers: × and ÷ | умножение · деление · смешанные (большие числа, три множителя, пропущенное число) |
| Powers & indices | положительные основания · отрицательные основания (−3)², (−2)³ · ловушки: −3² и (−3)², 2^? = 32, ?³ = −27 |
| Square & cube roots | √49, ∛64 · ∛−27, −√36, √25 + √16, (√9)² · оценка: √50 ≈ 7, ? < √88 < 10 |
| BIDMAS with powers | степень и одно действие · три действия, например (−3)² − 4 × 5 · скобки: (3 − 7) × 2, (−2 − 3)² − 5 |
| Substitution | одна буква (3x + 2, 5(x − 4)) · степени (x², 2x², x² − 3x) · две буквы (2a − 3b, (a + b)², a² − b²); везде с отрицательными числами |
| Fractions | эквивалентные дроби (сократить 12/18, 3/4 = ?/20, 3/5 от 40) · сложение и вычитание · умножение и деление (keep, change, flip) · смешанные числа |

По умолчанию в испытание входят уровни 1–2 тем «Negative numbers» и «Powers». Это меняется в For parents → Topics, отдельно для каждого ребёнка.

## Правила испытания

- Сет: 10 вопросов из выбранных тем вперемешку.
- Награда: 2 идеальных сета подряд в один день дают 30 минут игры.
- Любая ошибка обнуляет серию. Выход из сета на середине и закрытие страницы тоже обнуляют серию, чтобы нельзя было «пропускать» трудные вопросы.
- Практика по отдельным темам на награду не влияет.
- Ребёнок сам запускает таймер игрового времени. Таймер виден в шапке на всех устройствах.
- В настройках родителя для каждого ребёнка меняются: число вопросов, число сетов, минуты, лимит наград в день и поведение при ошибке.

Сайт не может сам заблокировать игры на компьютере: это договорённость, а родитель видит в панели, когда и сколько времени заработано. Если нужна жёсткая блокировка, её даёт родительский контроль системы (Microsoft Family Safety, Экранное время на iPhone, Google Family Link): там можно выдавать дополнительное время вручную.

## Синхронизация между устройствами

Общий прогресс телефона, компьютера и телефона родителя хранится на сервере, по одному «семейному» документу на код семьи. Подходит любой из двух вариантов:

- **Firebase (Google Cloud Firestore)** работает с любого хостинга, включая GitHub Pages. Если он настроен в `src/config.js`, сайт использует его.
- **`api/sync.php`** подходит для хостинга с PHP, например Бегета, и используется, только если Firebase не настроен.

### Настройка Firebase (один раз)

1. Создайте проект на https://console.firebase.google.com.
2. Build → **Firestore Database** → **Create database**. Location: `europe-west2 (London)`, режим **Production**.
3. Вкладка **Rules**: вставьте содержимое `firebase/firestore.rules` и нажмите **Publish**.
4. Впишите идентификатор проекта (⚙ → **Project settings** → Project ID) в `src/config.js`:

   ```js
   firebase: { projectId: 'study-quest-1b14b' },
   ```

   API-ключ не нужен: сайт обращается к Firestore напрямую, а доступ к данным ограничивают правила из шага 3. Каждая семья хранится в документе `families/<sha256 от кода семьи>`. Без кода документ не найти, а просматривать список документов правила запрещают.

5. Отправьте изменения в `main`, и GitHub Pages обновится сам.

## Home Assistant и Microsoft Family Safety

Цель: игры на компьютере и Xbox заблокированы всё время, кроме игрового времени, заработанного в Study Quest.

```
Study Quest ──сводка──▶ Firestore ◀──каждые 30 с── Home Assistant ──▶ Microsoft Family Safety ──▶ компьютер, Xbox
```

Сайт пишет в Firestore короткую сводку: до какого момента у каждого ребёнка идёт игровое время. Home Assistant читает только её. Открывать HA в интернет не нужно, а трафик укладывается в бесплатный тариф Firebase.

### Настройка

1. **Правила Firestore.** Вставьте полный текст `firebase/firestore.rules`, в котором есть блок `match /ha/…`, в Firebase → Firestore Database → Rules и нажмите **Publish**.
2. **Интеграция Family Safety.** В HACS откройте ⋮ → *Custom repositories* и добавьте `https://github.com/noiwid/HAFamilySafety` с типом *Integration*. Скачайте «Microsoft Family Safety» и перезапустите HA. Затем: Настройки → Устройства и службы → Добавить интеграцию → *Microsoft Family Safety*. Войдите родительским аккаунтом Microsoft и отметьте Xbox среди платформ.
3. **Найдите переключатели.** Панель разработчика → Состояния, поиск `_lock` и `_app_`. Для этих переключателей «включено» значит «заблокировано»: `switch.…_xbox_lock` блокирует Xbox, `switch.…_app_<игра>` блокирует игру на Windows. Сначала проверьте вручную: включите блокировку игры и убедитесь, что она перестала запускаться. Изменения доходят до устройства примерно за минуту.
4. **Study Quest.** For parents → Devices → Home Assistant → **Turn on the Home Assistant link**, затем **Copy for Home Assistant**.
5. **Пакет для HA.** Сохраните скопированный текст как `/config/packages/study_quest.yaml` (через File editor или Studio Code Server). В `configuration.yaml` должно быть:

   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```

   В блоке `group:` замените строки `CHANGE_ME` на свои переключатели из шага 3.
6. Панель разработчика → YAML → **Проверить конфигурацию**, затем **Перезапустить**.
7. Включите переключатель **Study Quest controls games**. Пока он выключен, автоматизации ничего не трогают.

### Как это работает

- **Таймер запущен.** Ребёнок нажимает «Start the timer», и не позже чем через 30 секунд HA снимает блокировки из группы. До устройства изменение доходит ещё примерно за минуту.
- **Время вышло** или ребёнок нажал «I've finished playing»: блокировки возвращаются. Каждые 10 минут и после перезапуска HA проверяет, что всё снова заблокировано.
- **Нет интернета** или Firestore недоступен: игры остаются заблокированными.
- **Защита от подделки.** Если в сводке время окончания стоит дальше чем на 4 часа вперёд, HA его не учитывает. По желанию в автоматизации можно включить уведомление на телефон родителя: оно приходит, когда игровое время началось.
- **Ограничения.** Интеграция использует неофициальный API Microsoft. Время от времени может понадобиться заново войти в неё, а обновление на стороне Microsoft может её сломать. Телефоны Family Safety почти не контролирует. Если у интеграции нет переключателя для телефона, ограничивайте игры там через «Экранное время» (iPhone) или Family Link (Android).

## Размещение на хостинге

Соберите сайт (нужен Node.js 18+):

```bash
node build.mjs
```

Получится папка `dist/site/`:

```
dist/site/          для хостинга с PHP
  index.html        весь сайт в одном файле
  api/sync.php      синхронизация между устройствами
  api/data/         здесь сервер хранит прогресс (защищено)
dist/pages/         для GitHub Pages и других хостингов без PHP
```

### Вариант 1. Свой хостинг с PHP (Бегет, dosmanov.com), с синхронизацией

1. Загрузите **содержимое** `dist/site/` в папку на хостинге. На Бегете это `dosmanov.com/public_html/study/`. Загрузить можно через файловый менеджер панели хостинга или по FTP.
2. Проверьте, что папка `api/data` доступна PHP на запись (обычно права 755 или 775).
3. Откройте `https://dosmanov.com/study/api/sync.php?ping=1`. Должно показаться `{"ok":true,"app":"studyquest","v":1}`.
4. Откройте `https://dosmanov.com/study/` и пройдите первую настройку: имя ребёнка и PIN родителя. Сайт покажет **код семьи** и ссылку для подключения.
5. Откройте эту ссылку на телефоне и компьютере сына. Чтобы видеть прогресс со своего телефона, подключите и его.
6. Второго ребёнка можно добавить в For parents → Family. На устройстве с несколькими профилями сайт сначала спрашивает «Who’s studying?» и запоминает выбор.

Нужен PHP 7.0 или новее, база данных не нужна. Каждая семья хранится в одном файле `api/data/<хеш>.php`. Файл начинается с `<?php exit; ?>`, поэтому его нельзя открыть из браузера даже там, где не работает `.htaccess`.

### Вариант 2. GitHub Pages: бесплатно, без синхронизации (работает сейчас)

Адрес: **https://dosmanoff.github.io/study-quest/**

- Сайт публикуется сам: при каждом изменении в `main` GitHub проверяет примеры всех тем, собирает сайт и выкладывает его (`.github/workflows/pages.yml`). Как идёт публикация, видно во вкладке **Actions** репозитория.
- Один раз нужно включить Pages: Settings → Pages → Source: **GitHub Actions**.
- Сервера там нет, поэтому синхронизации тоже нет. На каждом устройстве свой прогресс, а настройку (имя ребёнка, PIN родителя) нужно пройти один раз на каждом устройстве.
- Чтобы потом переехать на Бегет с синхронизацией: на каждом устройстве For parents → Data → Show backup, скопировать текст, затем на новом сайте For parents → Data → Restore from backup. Прогресс объединится.

Для других статических хостингов (Netlify, Cloudflare Pages) подойдёт `dist/pages/index.html`.

### Без интернета

`dist/study-quest.html` можно просто открыть двойным щелчком. Это тот же сайт без синхронизации.

## Business Quest (IB Business Management, Ярослав)

Отдельный сайт на том же ядре: **https://dosmanoff.github.io/study-quest/business/**. Тренировка IB Business Management, Unit 1 (подтемы 1.1–1.6, 100 вопросов, 435 баллов). Игрового времени, наград, лимитов и связи с Home Assistant здесь нет.

- **Quick check**: 10 заданий с мгновенной проверкой, около 7 тестов и 3 расчёта. Ошибки прошлого раза идут первыми, не больше 3 за сет.
- **Exam question**: вопрос из банка, ответ пишется текстом. Перед ответом показываются command term, его требование, совет и ориентир по числу слов. Черновик сохраняется сам.
- **Review due**: повторение по расписанию. Ниже 50% — через 1 день, ниже 80% — через 3 дня, при 80% и выше — 7, 14, 28 … дней, не больше 60.
- **Подтемы** и **Command terms** с markbands для вопросов на 10 баллов.
- **For parents** (под PIN): плитки, таблицы по подтемам, по AO и по command term, «Needs work», история с каждым ответом и разбором, очередь на проверку, настройки (имя, HL), устройства, бэкап.

### Как проверяются ответы

- Quick check и расчёты проверяет код в браузере.
- Письменные ответы проверяет Claude по mark scheme, **на стороне GitHub**. Задание `.github/workflows/mark.yml` запускается каждые 10 минут из Home Assistant (см. «Надёжное расписание»), по расписанию GitHub и вручную (кнопка «Mark now» в панели родителя открывает его страницу, там нужно нажать **Run workflow**). Задание берёт ответы со статусом `pending` из Firestore, собирает промпт (`marker/lib.mjs`) и вызывает Claude. Результат проверяется: балл целый и в пределах, при слишком коротком ответе балл ограничивается, если JSON не разобрался — один повтор. Оценка записывается обратно, и на устройства она приходит через синхронизацию.
- Пока ответ не проверен, он `pending`. Он не входит ни в баллы, ни в средние, ни в повторения, ни в «Needs work». Этот вопрос не выдаётся снова, а model answer к нему не виден. Самооценки нет. Если нет ключа, API недоступен, сработал rate limit или кончился дневной лимит, ответы просто ждут следующего запуска.
- Браузер ничего не знает ни о промпте, ни о ключе, ни о mark scheme. На сайт попадают только сами вопросы (`src/subjects/business/questions.js`). Полный банк с mark scheme лежит в репозитории только в зашифрованном виде (`marker/bank.enc`, AES-256-GCM). Model answer задание проверки дописывает к ответу ученика после проверки.
- Одну запись нельзя проверить дважды: задания идут по одному (`concurrency`), и каждый ответ перед вызовом Claude захватывается в Firestore с lease на 10 минут.

### Настройка (один раз)

1. **Семья.** Откройте https://dosmanoff.github.io/study-quest/business/ и задайте имя и PIN родителя. Сайт покажет **код семьи** и ссылку: откройте её на телефоне и компьютере Ярослава. Это отдельный код, не тот, что у Саши.
2. **Секреты GitHub.** Settings → Secrets and variables → Actions → **New repository secret**:
   - `ANTHROPIC_API_KEY` — ключ API с https://console.anthropic.com (Settings → API keys). В git и на сайт он не попадает.
   - `BQ_BANK_KEY` — ключ, которым зашифрован банк (его выдаёт `node tools/bank.mjs key` при подготовке банка; хранится у владельца).
   - `BQ_FAMILY_CODES` — код семьи из шага 1. Если семей несколько, коды через запятую.
3. **Проверка.** Actions → «Mark Business Quest answers» → Run workflow. В логе будет `Done: … marked`. Без ключа API задание завершается спокойно, а ответы ждут.

Firestore тот же, что у Study Quest (`study-quest-1b14b`), правила менять не нужно. Состояние семьи помещается в один документ: старые попытки при приближении к лимиту 900 КБ сохраняют только свой балл.

### Надёжное расписание (Home Assistant)

Расписание GitHub ненадёжно: в первые сутки задание из `mark.yml` запустилось по расписанию два раза за 11 часов вместо 66, потому что при нагрузке GitHub пропускает такие запуски. Поэтому задание проверки лучше запускать снаружи. У нас это делает Home Assistant, который и так работает круглосуточно:

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token. В Repository access выберите только `dosmanoff/study-quest`, в Permissions → **Actions: Read and write**. Больше ничего не нужно: таким токеном можно только запускать и смотреть задания этого репозитория.
2. В `/config/secrets.yaml` добавьте строку `github_business_quest: "Bearer github_pat_…"`. Слово `Bearer` и пробел после него обязательны.
3. Скопируйте `marker/homeassistant/business_quest_marking.yaml` в `/config/packages/`, проверьте конфигурацию и перезапустите HA. Если ответов в очереди нет, задание просто ничего не делает.

С 07:00 до 23:59 Home Assistant запускает проверку каждые 10 минут. Без него остаются кнопка «Mark now» в панели родителя и расписание GitHub.

Логи GitHub Actions в публичном репозитории видны всем. Поэтому задание проверки пишет в лог только «family 1», номера вопросов и баллы. Кода семьи, имени и текста ответов в логе нет.

### Модель, лимит и другие настройки

Файл `marker/config.json`:

| Поле | По умолчанию | Что делает |
|---|---|---|
| `model` | `claude-sonnet-5-5` | модель Claude для проверки |
| `fallbacks` | `"default"` | если модель отказалась отвечать, тот же запрос повторяется на запасной модели (серверный fallback). `null` — выключить |
| `effort` | `null` | глубина рассуждений (`low` … `max`); `null` — значение API по умолчанию |
| `dailyLimit` | `60` | сколько вызовов Claude в сутки (по UTC). Сверх лимита ответы ждут следующего дня |
| `maxTries` | `3` | сколько запусков подряд можно получить непригодный ответ модели, прежде чем запись оставят для ручного разбора |
| `leaseMinutes` | `10` | на сколько ответ захватывается одним запуском |

Чтобы сменить модель или лимит, поправьте файл и отправьте изменения в `main`. Можно и без коммита: задайте в workflow переменные окружения `BQ_MODEL`, `BQ_DAILY_LIMIT`, `BQ_EFFORT` или `BQ_FALLBACKS=off`.

Если в публичном репозитории больше 60 дней нет коммитов, GitHub выключает задания по расписанию совсем. Тогда достаточно снова включить workflow на вкладке Actions. Запуски из Home Assistant от этого не зависят.

### Банк вопросов

Открытый `src/subjects/business/bank.json` в git не попадает (`.gitignore`). Чтобы поправить вопрос или mark scheme:

```bash
echo "<BQ_BANK_KEY>" > .bank-key            # файл тоже не попадает в git
node tools/bank.mjs decrypt                  # marker/bank.enc -> bank.json
# правка bank.json
node tools/bank.mjs build                    # -> questions.js + marker/bank.enc
node tools/bank.mjs check
```

### Тесты Business Quest

```bash
node tests/business.test.mjs                 # задания и генераторы (по 1000 прогонов), парсер чисел, повторения, pending, merge, размер
(cd marker && npm ci) && node tests/marker.test.mjs     # cleanMark, промпт, 200/429/500, плохой JSON, отказ, «ignore previous instructions», нет ключа, лимит, lease
node build.mjs && node tests/business-ui.test.mjs       # браузер 380 px, тёмная и светлая темы: весь путь без ключа и с ключом
```

Без `BQ_BANK_KEY` тесты подставляют выдуманный mark scheme, поэтому идут и без секрета. Проверка задания и браузерный тест работают с имитациями Firestore и Claude, настоящий ключ не нужен.

## Пользователи

- **Родитель** входит по ссылке «For parents» внизу страницы с PIN родителя.
- **Дети**: у каждого свой профиль. Устройство запоминает, чей это профиль, а переключиться можно, нажав на имя в правом верхнем углу. Если у ребёнка задан PIN, его спросят при переключении на этот профиль, так что брат не зайдёт в чужой профиль.

## Панель родителя

Вкладки Progress, Rules и Topics относятся к ребёнку, выбранному вверху панели.

- **Progress**: сколько сетов решено сегодня, точность, темы, где больше всего ошибок, последние ошибки с ответами ребёнка, история сетов и игрового времени. Есть оценка, насколько реально пройти испытание при текущей точности.
- **Rules**: число вопросов, сетов, минуты, лимит в день, что делать при ошибке.
- **Topics**: какие темы и уровни входят в испытание.
- **Family**: добавить, переименовать или удалить ребёнка, задать или убрать PIN ребёнка, сменить PIN родителя.
- **Devices**: код семьи и ссылка для подключения устройств.
- **Data**: резервная копия, сброс прогресса ребёнка.

Если PIN родителя забыт, на экране ввода есть «Forgot the PIN?»: это стирает данные на текущем устройстве (нужно ввести слово RESET).

## Как добавить новую тему или предмет

Каждая тема — один файл в `src/subjects/<предмет>/`. Готовый пример с пояснениями: `src/subjects/_template/topic-template.js` (французские слова; там показаны ответы текстом и выбор из вариантов).

1. Скопируйте шаблон, например в `src/subjects/maths/fractions.js`.
2. Задайте `id`, `title`, уровни `levels` и функцию `generate(level)`, которая возвращает один вопрос:

   ```js
   {
     ask: 'Work out',                // подпись над вопросом
     prompt: '3/4 + 1/8 = [[?]]',    // HTML, [[?]] — место для ответа
     text: '3/4 + 1/8 = ?',          // простой текст для истории
     answer: 7,                      // правильный ответ
     input: 'integer',               // 'integer' | 'number' | 'fraction' | 'text' | 'choice'
     steps: ['...', '...'],          // разбор, который увидит ребёнок после ошибки
   }
   ```

3. Добавьте строку в `index.html` рядом с другими темами:

   ```html
   <script src="src/subjects/maths/fractions.js"></script>
   ```

4. Отправьте изменения в `main` на GitHub: GitHub Pages обновится сам. Для своего хостинга соберите (`node build.mjs`) и загрузите `dist/site/index.html` заново. Прогресс и настройки сохраняются.
5. В For parents → Topics отметьте новые уровни.

Для новых тем по математике есть помощники в `src/subjects/maths/helpers.js`: правильный знак минус, степени, пошаговое решение по BIDMAS.

## Проверка

```bash
node tests/generators.test.mjs
```

Генерирует по 4000 вопросов на каждый уровень каждой темы и проверяет ответы независимым калькулятором. Ещё проверяет разбор ответов и слияние данных с разных устройств.

```bash
node build.mjs && node tests/ui.test.mjs
```

```bash
node build.mjs && node tests/firebase.test.mjs
```

Синхронизация через Firestore на имитации его REST API (те же адреса, условия сохранения и правила): создание семьи, подключение телефона по ссылке, одновременные сохранения с двух устройств, неверный код, закрытая база. Там же проверяется сводка для Home Assistant.

```bash
python3 tests/homeassistant_test.py
```

```bash
node build.mjs && node tests/fractions-ui.test.cjs
```

Ответы-дроби в браузере на экране телефона: экранная клавиатура, просьба сократить, смешанные числа, подсказки, ввод с клавиатуры.

Пакет для Home Assistant: YAML разбирается, названия сущностей сходятся, а шаблоны, отрисованные в Jinja2 с помощниками HA, дают правильное оставшееся время для случаев «таймер идёт», «закончился», «сводки нет», «подделка» и «датчик недоступен».

Полный сценарий в браузере с PHP-синхронизацией (нужны Playwright и PHP): настройка, испытание, ошибка, награда, подключение телефона по ссылке, практика с экранной клавиатурой, панель родителя, синхронизация настроек, второй ребёнок со своим PIN и правилами, удаление профиля.
